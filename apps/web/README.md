# Ascend Web

React and Vite Project Home for registered Ascend projects. Use root `justfile` commands only. Vite proxies same-origin `/api` traffic to the loopback API; the owned browser test overrides only that target.

Project Home loads exact four-field projects with a 5,000 ms bound and renders loading, empty, failure/retry, and deterministic `createdAt ASC, id ASC` card states. Its semantic `Open Project` form has a persistent `Host path` label and associated guidance for absolute, `~`, and `~/...` notation. The controlled value is preserved exactly. Blank input and all backend path categories publish an associated alert, set `aria-invalid`, retain input, focus the field, and change no card.

The registration client serializes `{"path":"<exact input>"}` once. Ordinary and retry requests have a 10,000 ms bound. While pending, duplicate activation is blocked and active Cancel is available. Created or existing responses upsert solely by stable ID, sort cards, scroll the exact returned action into view, focus it, and announce the disposition without reload. Equivalent paths therefore update one card rather than matching name or path text.

Only controlled positive pre-send unavailability is definitely not transmitted. After fetch invocation, timeout, connection reset or rejection, truncated or unreadable body, non-JSON, undocumented status, and invalid response shape enter announced `Submission outcome unknown`. The input and visible exact payload are locked; idle recovery exposes only `Retry same submission` and `Refresh projects`. Retry uses byte-equivalent JSON and active Cancel returns to the same locked state.

A valid refresh replaces the complete authoritative list and compares only IDs with the pre-submit snapshot. One added ID is focused and reconciled. Zero added IDs preserves authoritative cards, unlocks the original input, and announces no new project. Multiple additions preserve the complete list, select no identity, and require explicit reset before another payload. Failed, timed-out, or invalid refresh preserves current cards and locked payload. One monotonic request generation invalidates stale completion after every request, cancellation, timeout, refresh, reset, newer list, and unmount.

All path, payload, name, and canonical-path values render as inert complete whitespace-preserving React text. Card Open is a stable-ID keyboard action that navigates to `/projects/{encodedStableId}/workbench/` with one trailing slash. Eight repeated activations join one navigation generation. The URL contains no name or canonical path. Picker, scanning, clone/import, running or failed workbench close, search, sorting controls, tags, path mutation, Restart, auto-sleep, and scheduling remain deferred. Selected Stop is delivered below.

Validate with `just verify-open-project`, targeted `just verify-focused <test-path>`, and `just verify`. The keyboard-only desktop Chromium episode uses isolated database and host fixtures and retains its executed success in `test-results/bl-008/open-project/episode.json`. `cleanup-matrix.json` separately maps executed startup-failure, assertion-failure, episode-timeout, interrupted-graceful-shutdown, and surviving-descendant scenarios to process-group, listener, database/sidecar, and fixture counts. Interrupted graceful shutdown records bounded escalation. The survivor is detected with `ownerCleanupPassed: false` until exact-PID test teardown, then `teardownClean: true`; the documentation does not represent that scenario as an all-true cleanup owner result.


## Close interaction (BL-009)

Every registered card exposes exactly one semantic Close action. Activation opens an aria-modal dialog named Close <project name>? with this exact copy: Closing removes this project registration from Ascend. The filesystem directory and files will not be deleted. Project names, paths, IDs, announcements, and fixed errors remain inert React text, including whitespace and HTML or script metacharacters. Component and client matrices execute one-character and 4,096-character bounded name/path fixtures; 4,096 characters is an exercised test bound, not a new product field maximum. The existing registration wire limit remains 4,096 encoded body bytes and rejects byte 4,097.

Tab and Shift+Tab wrap through available controls. Escape and Cancel before transmission restore the activating Close action and send no request. Destructive Confirm starts one bounded 10,000 ms DELETE for the captured stable ID; repeat activation cannot start another. After transmission, Cancel is unavailable and pending or recovery is announced. Success removes only that ID without navigation, then focuses next Close, previous Close, or the Ascend heading and reveals the existing final-card empty state.

Exact 400 invalid_project_id and 500 project_close_failed outcomes prove no mutation and expose Retry for the same ID. Malformed or unencodable IDs fail before transmission. A 404 project_not_found or any post-transmission timeout, reset, unreadable response, undocumented status, or invalid contract is unknown: the card remains and only Refresh projects is available. The strict 5,000 ms authoritative list decides by the original ID. Presence enables Retry, absence applies normal success, and failed or invalid lists stay locked for another refresh. Repeated controls own at most one request, and stale, cancelled, timed-out, or unmounted completion changes no card, dialog, focus, announcement, or recovery state.

Use just verify-close-project and just verify. The keyboard-only Chromium success and separate controlled-fault episode retain integrity-before-cleanup and zero-owned-residual evidence. Running or failed workbench close, Restart, archive, undo, bulk close, and product cleanup remain BL-020 or later. Selected Stop is a separate non-destructive runtime action and never removes the card.

The fixed safe close messages are: The project ID is invalid. Retry this project. The project is no longer registered. Refresh projects to reconcile. The project could not be closed. Retry this project. Server-provided error text is never rendered.

## Stop workbench interaction (BL-017)

Every registered card has one `Stop <project name> workbench` button with the accessible description `Stopping releases the workbench and keeps the project registered.` Stop has no destructive confirmation dialog. One monotonic Home owner serializes it with registration and Close operations. While pending, every Stop button is disabled, the selected card is `aria-busy`, and a polite status announces the transition.

The client sends one bodyless `POST /api/projects/{encodedStableId}/runtime/stop` with a finite 10,000 ms transport bound. It strictly accepts only exact `stopped` or `already-stopped` success bodies or one of the nine bounded error categories; extra, missing, unknown, wrong-status, or server-message fields make the outcome indeterminate. All displayed error text comes from the client-owned notice catalog.

Success and already-stopped each restore focus to the selected Stop action, announce that the project remains registered or was already stopped, and trigger exactly one fresh runtime-state projection. The card displays `Stopped` only from that reconciled response. Rejection preserves all cards and metadata, exposes a bounded alert and same-ID Retry, and performs no projection refresh. An indeterminate result is never assumed successful; it remains explicitly unknown with `Refresh runtime state`.

Use `just verify-runtime-stop` for transport, controller, component, accessibility, stale-settlement, metadata, peer, and disclosure matrices. `just proof-runtime-stop` and `just proof-runtime-stop-residual-audit` prove the designated manager-owned runtime release outside the browser. Stop adds no browser timer, polling, stream, health probe, configuration, migration, or deployment-specific behavior.


## Home and workbench navigation (BL-012)

Project Home remains the exact `/` route. Open uses full-document navigation rather than a client router so refresh, Back, Forward, and direct stable URLs retain native browser behavior. Vite forwards `/projects` HTTP and WebSocket traffic to the loopback API on the same browser origin; deployment routing must provide the same ownership. The workbench's Projects link returns to `/` without stopping its runtime. Loading is a polite status; fixed failures are assertive alerts with one-time heading focus. Retry is present only for retryable load failures and does not add history.

The web proxy and API must use the same private ASCEND_FRONT_DOOR_TOKEN. Unset local development uses the shared built-in development value; explicit values must be 16–256 characters, and deployment proxies must inject the trusted authority/token pair without logging it. This changes configuration guidance but requires no data, schema, or API-payload migration. Validate with `just verify-home-workbench`, focused tests through `just verify-focused`, and the complete `just verify` gate.
