# Research Brief: BL-002: Prove host-native terminal parity

## GitHub Issue
- **Issue:** #7
- **Title:** BL-002: Prove host-native terminal parity
- **Work Item:** project/work-items/7-bl-002-prove-host-native-terminal-parity

## Scope Classification
- **Scope Type:** issue

## Problem Statement
Ascend does not retain bounded proof that a code-server integrated terminal and direct commands executed by the configured `vscode` host user observe the same designated host, user, canonical BL-001 fixture directory, required tool behavior, and limited tool-resolution environment. Issue #7 limits this validation to the designated Ubuntu 24.04 devcontainer, its runtime hostname, code-server 4.131.0, and six installed tools. It excludes tool installation, alternate hosts, presentation comparisons, concurrent starts, session persistence, lifecycle UI, recovery, production operation, broad security validation, and exhaustive environment equality.

## Acceptance Criteria

**Core**
- [ ] One paved repository command starts the merged BL-001 workbench against its canonical fixture directory, opens one integrated terminal through bounded Chromium automation, runs the fixed command list, and has one documented overall timeout that returns nonzero when exceeded.
- [ ] In the same run, normalized direct and integrated outputs for `hostname` and `id -un` match, and both user results equal `vscode`.
- [ ] The integrated terminal result for `pwd -P` equals the canonical fixture path supplied when the BL-001 workbench was launched.
- [ ] The fixed tool command list is exactly `git --version`, `git status --short`, `gh --version`, `tmux -V`, `docker --version`, and `copilot --version`; direct and integrated invocations run from the canonical fixture directory, their exit results and normalized stdout/stderr match, and evidence records each finite timeout, exit result, stdout, and stderr.
- [ ] The repository documents one content-preserving normalization applied identically to direct and integrated results and retains references to both raw results.
- [ ] Only a repository-defined environment allowlist needed for tool resolution is compared; each allowlisted variable receives an `equal`, documented `allowed difference`, or `unexplained failure-causing difference` result, and any unexplained failure-causing difference makes the paved command nonzero without retaining non-allowlisted environment values.

**Failure and cleanup**
- [ ] A missing fixed-list executable produces one documented pre-browser nonzero result naming the executable; an executable that exists but returns nonzero produces a distinct nonzero result naming the command and whether the failure was direct or integrated; a per-command timeout is also nonzero and names the command and context.
- [ ] Every executed success or named-failure path stops the exact BL-001 process group, confirms its PID and listener are absent, closes any opened browser context, and leaves no terminal command started by the validation running.

**Evidence**
- [ ] One retained evidence record maps every criterion to commands, timeouts, exits, normalized outputs, raw artifact references, and results, and records Ubuntu version, runtime hostname, user, shell, fixed-list tool versions, code-server version, cleanup outcome, and overall disposition.
- [ ] Documentation records prerequisites, the exact fixed command list, allowed environment differences, the exact paved command, timeout, diagnostics, cleanup, and the observed designated-host result.
- [ ] `just verify` exits zero.

## Constraints
- Issue #7 fixes the validation boundary to the current Ubuntu 24.04 devcontainer, runtime hostname, `vscode` user, canonical BL-001 fixture, code-server 4.131.0, and the six named installed tools. Portability, installation, alternate hosts, presentation comparison, concurrent workbenches, persistence, recovery, production operations, broad security testing, and exhaustive environment equality are excluded.
- The command list and contexts are acceptance constraints: host and identity comparison occurs in one run; `pwd -P` must identify the launched canonical fixture; and the six tool commands must remain exactly as stated, with both contexts running from that fixture.
- Comparisons are bounded by an overall timeout and finite per-command timeouts. Missing executables must fail before browser use; nonzero commands and timeouts must identify both command and execution context.
- The issue permits comparison and retention only for a repository-defined environment allowlist needed for tool resolution. Non-allowlisted environment values cannot be retained. The existing child launch fields in `buildEnvironment` do not by themselves define comparison variables, allowed differences, or failure classification.
- The canonical fixture contains a space and literal semicolon. `CORE-COMPONENT-260808-filesystem-path-safety.md` requires canonical directory use and prohibits shell construction from untrusted paths; `CORE-COMPONENT-260808-host-process-environment.md` requires argument arrays, configured-user execution, deterministic tool resolution, and canonical terminal working directories.
- Exact cleanup remains tied to the BL-001 handle and process group. Every path that actually opens a browser or starts terminal commands must satisfy the issue requirement for browser-context closure, terminal-command absence, and PID/listener absence; process-name kills and broad listener sweeps remain unsafe on this host.
- Runtime lifecycle failures must be explicit and actionable under `CORE-COMPONENT-260808-runtime-lifecycle-error-handling.md`. The accepted BL-001 runtime boundary already owns start, exact stop, identity validation, and bounded escalation.
- `CORE-COMPONENT-260808-structured-runtime-logging.md` prohibits terminal contents and command output in runtime logs, while Issue #7 requires command outputs in retained proof. Any retained records remain subject to the issue allowlist and repository privacy boundary and cannot be treated as unrestricted lifecycle logging.
- The root `justfile` is the canonical command surface under `CORE-COMPONENT-260806-project-command-interface.md`; full validation remains `just verify`. Harness checks delegate to that gate and currently impose a 120-second wrapper bound.
- Browser interaction remains Chromium-based under the accepted TypeScript stack. code-server owns the integrated terminal; Ascend owns the bounded runtime lifecycle. Stable Ascend routing and application workbench UI are not present and are outside Issue #7.
- Research may record repository state and unresolved requirements only. The definitions of normalization, comparison allowlist, allowed differences, artifact layout, command orchestration, and browser interaction are not established by current repository evidence.

## Risks and Open Questions
- No current browser test opens an integrated terminal, captures its three streams and exit status, or proves terminal child-process cleanup. The behavior of code-server 4.131.0 terminal automation on this isolated user-data directory is therefore unobserved in repository evidence.
- The designated account shell is `/bin/zsh`, the BL-001 launch environment exports that shell, and `.vscode/tasks.json` contains a folder-open task that explicitly invokes bash in a terminal. It is unresolved whether the isolated code-server episode runs that task, creates an additional terminal, prompts for task approval, or otherwise affects the one-terminal boundary.
- Shell initialization may alter PATH or other tool-resolution variables after code-server receives `buildEnvironment`. No real integrated-terminal environment has been retained, and the repository does not define which variables form the comparison allowlist or which differences are allowed.
- The issue requires one content-preserving normalization but does not define it. Existing records do not establish treatment of line endings, terminal control sequences, prompts, command echo, trailing whitespace, version update notices, or stream boundaries.
- Raw direct and integrated outputs are required, but runtime logging contracts prohibit command and terminal output and non-allowlisted environment retention. The repository does not currently identify the raw-artifact location, retention status, redaction boundary, or relationship between ignored machine artifacts and the retained evidence record.
- `git status --short` is intentionally state-dependent. It was empty before this brief was created, but later RPIV artifacts or other workspace changes can alter both raw outputs; repository evidence establishes no snapshot or mutation policy beyond same-run comparison.
- Current BL-001 browser cleanup stops the exact process group in `finally`, but browser-context lifecycle is left to the Playwright fixture and `runJust` has no independent timeout. Issue #7 adds explicit browser-context closure, command timeout, and terminal-process absence obligations that current evidence does not cover.
- The Issue #7 overall timeout is not numerically specified. Its execution must coexist with BL-001 startup/stop/browser bounds, the current 60-second Playwright test bound, the 120-second `just verify` harness-check wrapper, and the 150-second harness-boot wrapper; no repository record defines their intended relationship.
- Existing BL-001 machine evidence is generated and ignored, while Issue #7 requires retained raw references and a retained criterion map. The repository does not yet establish whether the existing BL-001 evidence boundary is sufficient for the new output-retention requirements.
- The direct designated-host observations confirm that all six executables currently resolve and return zero, but tool versions and the runtime hostname are host-state facts rather than portable constants. A rebuilt designated environment can change them while remaining within the issue wording.
- The fixed Copilot version command emits an update advisory in addition to its version, and GitHub CLI emits a release URL. The issue requires content-preserving comparison, but repository evidence does not establish whether integrated terminal rendering introduces control bytes or formatting around those outputs.
