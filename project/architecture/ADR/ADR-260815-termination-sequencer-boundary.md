# ADR-260815-termination-sequencer-boundary: Prove Termination Sequencing Through an Injectable Primitive Boundary

## Status

Accepted

## Context

`ADR-260815-selected-runtime-stop-control` requires a selected stop to offer a documented graceful opportunity before any escalation and to settle within a documented finite overall bound. Issue #39 AC-2 requires a controlled graceful case, a controlled escalation case that escalates *only after* that limit, and a controlled escalation-failure case, each with an inspectable classification and elapsed outcome.

The delivered termination machinery cannot prove any of that today. `terminateGroup` in `apps/api/src/project-runtime-process.ts` is module-private. It calls `process.kill(-pid, ...)`, `Date.now()`, a `setTimeout`-backed `delay(20)`, a `/proc` directory scan, and a loopback connection attempt directly, and it is reachable only from the closure that `nodeRuntimeProcessAdapter.launch` returns for a really spawned process. Every existing validation seam replaces that closure wholesale: a fake `terminate` that resolves `{ outcome: 'escalated' }` proves that a label was returned, not that no force signal preceded the graceful limit, and not that any deadline was honoured.

Three further gaps follow from the same boundary. First, a proposed `stopAuditAllowanceMs` can be summed into a documented overall bound while no code ever receives or enforces it, which makes the "documented finite overall bound" declarative. Second, `terminate` has no cancellation input and no self-imposed deadline, so a termination that never settles leaves its caller awaiting forever; for selected stop that strands an entry in `stopping` and never settles the public state. The deadline gap is not only between waits: `terminateGroup` awaits an identity read, a `/proc` directory scan, and a loopback connection attempt on every audit pass, and none of those calls can be cancelled or abandoned. A single primitive that never settles blocks the sequencer inside an `await` where no elapsed-time comparison is ever reached, so a bound expressed only as a loop condition is unenforceable, and a caller-side race bounds the caller without making the sequencer's own claim true. Third, the audit's `processGroupAbsent` field is produced by scanning `/proc/<pid>/stat` for process-group membership only, and escalation is currently attempted whenever that scan reports members, without revalidating that the owned root identity is still alive — so an unconfirmed, unescalated release is nevertheless reported `escalated`, and a signal can in principle be sent to a process group whose leader identity Ascend can no longer attribute to itself.

Three further defects sit inside the bound itself, and each one silently falsifies a claim the criterion depends on. First, a deadline can be circular: if every awaited primitive may fail to settle or ignore cancellation, then arming the sequencer's deadline with one of those same awaited primitives — an unawaited `delay(overall, signal)` — leaves the sequencer unbounded precisely when the hostile primitive is that delay, because nothing ever aborts the controller and every raced call waits forever. A deadline mechanism can only bound fallible work if it is not itself fallible work, and it must not depend on the very signal it exists to fire. Second, an `AbortSignal` that is already aborted when the sequencer is called never fires a newly registered `abort` listener, so a termination whose caller had already cancelled would still run to its full deadline before settling. Third, computing the graceful deadline from sequencer entry silently shortens the graceful opportunity by whatever the pre-signal observation cost: one full audit plus one identity read that consume 900 ms of a 2,000 ms period leave only 1,100 ms between `SIGTERM` and `SIGKILL`, while AC-2 requires a graceful shutdown opportunity bounded by the documented finite limit *before* escalation, and the delivered `terminateGroup` already starts its grace deadline after the send.

Two final ambiguities sit at the primitive boundary itself, and each one silently falsifies an elapsed-time claim the criterion depends on. First, a signal primitive that returns nothing cannot tell the sequencer whether its signal was delivered. The sequencer's own rule is that a phase window exists only after a real send, but a `void` `signalProcessGroup` collapses three different results into one: a delivered signal; the expected identity-to-signal race in which the owned group vanished between the revalidating identity read and the send, so `process.kill` reports `ESRCH`; and a genuine host fault such as a permission error. Opening a graceful window on a refused signal waits out a period no signal ever started, recording a refusal as a delivered signal or as an escalation makes trusted AC-2 evidence false, and swallowing an unexpected `kill` error hides a real termination fault behind an ordinary unconfirmed release. Second, `now()` was bound to `Date.now()`, a wall clock. Every phase deadline, every window, and the overall bound are elapsed-time arithmetic, so a forward wall-clock adjustment makes the sequencer believe the graceful period elapsed and deliver `SIGKILL` early in real elapsed time, and a backward adjustment stretches or inverts phase arithmetic. The self-bound timer itself stays real because it is a host timer, but the promise of a full graceful period after the actual graceful signal is only true when the clock that measures that period cannot be adjusted.

Issue #39 also constrains the fix. It excludes arbitrary-process adoption and unrelated-process termination, so a contrived `SIGTERM`-ignoring host process is not an acceptable proof vehicle. It excludes new configuration and deployment surface, so an operator-visible timeout variable is not acceptable. And it requires an ownership audit that confirms "no process remains attributable as its owned descendant", which forces an explicit statement of what makes a process attributable.

## Decision

Keep exactly one termination control flow, and make that one control flow injectable, bounded, cancellable, and attributable.

Export the sequencer as the single definition. `terminateOwnedRuntimeGroup(request: RuntimeTerminationRequest): Promise<RuntimeTerminationAudit>` replaces the private `terminateGroup` and remains the only implementation of graceful-then-force sequencing, waiting, auditing, and outcome classification. No caller, adapter, test, or evidence helper may re-implement, copy, or shadow that sequence.

Inject only the host primitives, never the sequence, give every awaited primitive a cancellation contract, and separate the primitives the sequencer trusts from the primitives it treats as fallible. `RuntimeTerminationPrimitives` has seven members in two trust classes with fixed shapes. The four fallible awaited primitives are `readProcessStartTime(pid, signal)`, `readProcessGroupMembers(processGroupId, signal)`, `listenerIsAbsent(port, signal)`, and `delay(milliseconds, signal)`; each is asynchronous and each takes a required `AbortSignal`, and each is treated as able to never settle and to ignore that signal. The three trusted synchronous primitives are `signalProcessGroup(processGroupId, signal: NodeJS.Signals): boolean`, `now(): number`, and `scheduleDeadline(milliseconds, onDeadline)`; none returns a promise, so signal delivery, clock reads, and deadline arming can never block the sequence. `signalProcessGroup` reports whether its signal was delivered, and `now()` reads a monotonic elapsed-time source rather than a wall clock; both contracts are decided below. `scheduleDeadline` invokes `onDeadline` at most once, no earlier than the requested delay, and returns a synchronous cancellation handle that prevents any later invocation; it deliberately accepts no `AbortSignal`, because the mechanism responsible for firing the sequencer's abort must not depend on that abort. The sequencer's bound therefore rests only on `now()` and `scheduleDeadline`, never on any awaited primitive, and no documentation, evidence, or validation surface may describe all seven primitives as equally fallible or describe an awaited primitive as a deadline source. Every awaited implementation must abandon its host work and settle promptly once the supplied signal aborts, and must never report an absence it did not observe, even though the sequencer never relies on it doing so. `defaultRuntimeTerminationPrimitives` binds them to the delivered host implementations — with `signalProcessGroup` over `process.kill` and `now()` over the monotonic `performance.now()` rather than `Date.now()` — and honours that signal wherever the host API allows it: `/proc` reads pass the signal to `readFile`, the loopback probe destroys its socket and settles on abort, and the delay clears its timer on abort. Where the host API accepts no signal — the `/proc` directory scan — the primitive still settles on abort by abandoning its remaining iteration. Its `scheduleDeadline` is a native `setTimeout` timer owned directly by the sequencer, cleared through the returned handle on every exit path, so the production deadline is real host machinery rather than a validation-only affordance, and validation exercises that production wiring alongside a clock-driven injected scheduler. `createNodeRuntimeProcessAdapter(primitives)` builds a process adapter over a chosen set while `nodeRuntimeProcessAdapter` remains the production default built from the defaults. Validation constructs an adapter over recorded primitives and therefore executes the same branches, the same ordering, the same deadlines, and the same classification that production executes. Replacing the whole `terminate` closure remains available for coarse manager-level race ordering, but it can no longer be the proof of sequencing behavior.

Make the audit allowance a real, code-enforced bound. `ProjectRuntimeConfig` gains `stopAuditAllowanceMs` with the same positive-safe-integer validation as its siblings. The process adapter binds the launching configuration's value into every `terminate` closure it creates, so every termination path — start-failure cleanup, the guarded running-to-failed transition, selected stop, and manager shutdown — passes a real allowance into the sequencer rather than relying on an implicit default. The sequencer settles within `gracefulMs + forceMs + auditAllowanceMs` measured on `primitives.now()`: the graceful wait is bounded by the graceful period counted from the graceful signal, the force wait by the force period counted from the force signal, and all pre-signal observation plus both inter-phase settlements by the allowance.

Make that bound self-enforcing rather than declarative, and arm it with something that cannot itself hang. On entry the sequencer computes `overallDeadlineAt` and creates one sequencer-owned `AbortController`. That controller is aborted by exactly three triggers: the caller's optional signal, the overall deadline callback, and the sequencer's own return. The overall deadline is armed once through `scheduleDeadline`, never through an awaited primitive, so a `delay` that never settles or ignores cancellation can no longer prevent the abort it is supposed to trigger; `delay` is the poll interval only. Every awaited primitive call is made through one internal helper that takes the deadline of the phase it belongs to, arms that per-call deadline through the same trusted scheduler, races the call against a call-scoped abort chained to the sequencer's controller, and returns an explicit abandoned marker when the abort wins. A primitive that ignores its signal therefore cannot extend the sequence: its promise is detached with an inert settlement handler, and its eventual value is never read, never recorded, and never able to produce a signal, an audit field, an outcome, or a mutation. The sequencer contains exactly one such helper and makes no awaited primitive call outside it. Every scheduler handle is cancelled and every abort listener removed on return, so no timer, listener, or unhandled rejection survives the call.

Observe an already-cancelled caller before doing anything else. A signal that was aborted before `terminateOwnedRuntimeGroup` was called never fires a newly added listener, so the sequencer synchronously evaluates the caller signal's aborted state on entry and, when it is already aborted, aborts its own controller in that same step and returns the non-confirming audit as `unconfirmed` before any audit, identity read, signal, wait, or deadline arming, having called no primitive other than the clock. Cancellation that arrives later is handled by the listener, as before.

Make signal delivery a result the sequencer can act on. `signalProcessGroup(processGroupId, signal: NodeJS.Signals): boolean` returns `true` only when `process.kill(-processGroupId, signal)` succeeded, returns `false` only for the expected identity-to-signal race in which the owned group is already gone and `process.kill` reports `ESRCH`, and rethrows every other error so an unexpected signalling failure surfaces as a termination fault instead of an ordinary unconfirmed release. Only a `true` return is a delivered signal: the sequencer reads the clock for `sigtermAt` or `sigkillAt` in the same synchronous step immediately after that return, and fixes the phase deadline from it. A `false` return delivers nothing, so it opens no window, is never recorded as a delivered signal, and can never make an outcome `escalated`. A refused graceful signal ends the sequence with exactly one bounded settlement audit inside the window that signal would have opened, and reports `already-absent` only when that audit completes and confirms all three absences with no signal delivered anywhere in the sequence, otherwise `unconfirmed`. A refused force signal ends the sequence `unconfirmed` immediately, because a graceful signal was already delivered and no member of the four-value outcome vocabulary can truthfully describe a confirmed release after a force signal that was never delivered.

Measure every phase window from the signal it bounds, not from sequencer entry. The graceful window runs for the full configured graceful period after the `SIGTERM` send that the signal primitive confirmed delivered, and the force window for the full configured force period after the confirmed `SIGKILL` send; each deadline is fixed from a clock reading taken in the same synchronous step as the delivering send returned, so escalation always follows at least a full graceful period after the delivered graceful signal. The audit allowance is what makes those full windows fit the unchanged overall bound: the sequencer reserves a small settlement share of the allowance for the two synchronous inter-phase settlements and the final return, and spends the rest as a pre-signal allowance that bounds all observation performed before the graceful signal. Pre-signal observation that does not complete inside that allowance ends the sequence as an unconfirmed release with no signal sent, rather than stealing time from the graceful opportunity or pushing the force window past the overall bound. A window exists only after its own delivered signal: when the escalation gate refuses because the sequence was cancelled or the group is no longer attributable, or when the signal primitive itself reports the target already gone, the sequencer returns without waiting out a force window it never opened.

Never turn an abandoned observation into a confirmed release. An audit attempt whose identity read, owned-group read, or listener probe was abandoned is discarded rather than completed with defaults, because a call that did not return is not an observed absence. The sequencer keeps the last audit whose three components all completed; if its deadline arrives before any audit completes, it returns a non-confirming audit whose three absence booleans are all false. Confirmation therefore always rests on completed observations, and the worst case of a broken or hostile primitive set is an unconfirmed release with retained ownership, never a false `Stopped`.

Measure termination on a monotonic clock, not a wall clock. `now()` is the sequencer's trusted elapsed-time source, and every value derived from it — the entry reading, the pre-signal allowance, both delivered-signal readings, both phase deadlines, and the overall deadline — is elapsed-time arithmetic rather than a point in civil time. `defaultRuntimeTerminationPrimitives.now` is therefore bound to the monotonic `performance.now()` rather than to `Date.now()`, so no forward or backward wall-clock adjustment can make the sequencer believe a graceful period elapsed and escalate early, or stretch a phase it has already entered. The trusted scheduler stays an independent native timer, so the deadline and the clock remain two separate mechanisms. Nothing else moves: the manager's runtime clock, lifecycle-event timestamps, health-check elapsed values, and every other delivered `Date.now()` use are unchanged, because they record when something happened rather than bounding a termination phase. Validation keeps driving the sequencer through an injected controlled clock, which is what makes the phase arithmetic deterministic, and documentation and evidence describe these readings as monotonic elapsed values so no reader treats them as wall-clock timestamps.

Make termination cancellable and keep exactly two enforcement points. `terminate(gracefulMs, forceMs, port, signal?)` accepts an optional `AbortSignal`, which the sequencer merges into its own controller. The sequencer checks that controller on entry, before every wait, and immediately before every signal send; because `signalProcessGroup` is synchronous, the check, the send, and the reading of the delivered signal's clock position occur in one step that no detached continuation can interleave, so nothing is sent after cancellation or after the deadline and no window is opened by a signal that was not delivered. It then returns the last completed audit. The selected-stop caller keeps the second, independent enforcement point: it races the awaited termination against an injected sleep for the same overall bound, aborts the signal when that backstop wins, settles its own entry, and counts the abandoned settlement in the manager audit instead of discarding it silently. The sequencer's self-bound is what makes the documented bound true of the shipped sequencer; the caller backstop is what keeps the manager settling even if a primitive set violates its contract in a way the internal race cannot observe. A late-settling termination therefore records nothing, mutates nothing, signals nothing, and emits nothing.

Signal only what Ascend can still attribute. Before any signal the sequencer revalidates the exact root identity — process ID plus recorded process start time — and tracks attribution across the call: an observation of a live root makes the owned group attributable; an observation of an empty owned group makes it unattributable again, because a free process-group identifier can be reassigned. `SIGTERM` and `SIGKILL` are sent to the owned group only while attribution holds. When attribution does not hold, the sequencer signals nothing and reports the release unconfirmed rather than signalling a group it cannot claim. Attribution is a precondition for attempting a send, not a guarantee that the send lands: the host may still refuse an attributable send because the group has just gone, which the delivery result reports and which opens no window.

Report an unconfirmed release as its own outcome. `RuntimeTerminationOutcome` becomes `already-absent`, `graceful`, `escalated`, and `unconfirmed`. `already-absent` means absence was confirmed with no signal delivered anywhere in the sequence, `graceful` means the graceful signal was confirmed delivered and absence was confirmed within the graceful period that followed it, `escalated` means the force signal was confirmed delivered to the attributable owned group and absence was confirmed after it, and `unconfirmed` means the windows elapsed, the sequencer's deadline arrived with an observation still outstanding, or a signal the sequence depended on was refused by the host, without confirming absence. Neither `graceful` nor `escalated` is reachable without its own confirmed delivered signal. The audit's three absence booleans remain the only confirmation of release; the outcome describes how the release was pursued and never substitutes for that confirmation.

Define owned-descendant attribution explicitly and do not overclaim it. A process is attributable to a runtime when it is a member of the process group led by that runtime's exact recorded root identity. `processGroupAbsent` keeps its delivered name and its delivered meaning: no process currently carries the owned process-group identifier. A descendant that leaves the owned group by calling `setsid` or `setpgid` before the audit samples it is, by this definition and by every bounded local mechanism available to Ascend, no longer attributable to the runtime, and Issue #39 forbids adopting or terminating processes Ascend cannot attribute. That ceiling is recorded wherever the audit is documented or serialized as evidence. Where an exact identity-bearing closure *is* obtainable — the designated real-host episode — the owned group's members are enumerated with their own process start identities immediately before the stop and each recorded member is re-probed after it, out of process, so the strongest available descendant proof is produced exactly where it can be honest.

| Enforce the overall bound only in the caller | Smallest process-layer change | The sequencer could still block indefinitely inside an audit primitive, and the caller can only abandon it | The bound must be honoured where the waiting happens, with a caller-side backstop |

## Consequences

### Positive
- The graceful opportunity, the escalation point, the force window, the audit allowance, and the overall bound are executed by validation exactly as production executes them.
- `stopAuditAllowanceMs` is a real bound enforced by code on every termination path instead of a number that only appears in documentation.
- A termination that never settles can no longer strand a caller, and a primitive that never settles can no longer strand the sequencer: the deadline is armed by a trusted synchronous scheduler that no awaited primitive can block, every awaited primitive receives a call-scoped deadline signal and is abandoned if it outlives it, the caller backstops, cancellation is honoured, and abandonment is counted rather than hidden.
- A caller that has already cancelled gets an immediate unconfirmed settlement with no primitive call, no signal, and no wait, instead of a full-deadline delay.
- The graceful opportunity and the force window are each the full configured period after their own signal, so escalation timing can be asserted directly from the two signal timestamps rather than inferred from operation start.
- An abandoned observation can never become a confirmation, so a hung or hostile primitive set degrades to an unconfirmed release with retained ownership instead of a false release.
- No signal is ever sent to a process group whose owning root identity cannot currently be attributed to Ascend.
- Evidence distinguishes "escalated and confirmed" from "never confirmed", so no unconfirmed release is described as an escalation that happened.
- A refused signal is distinguishable from a delivered one, so no phase window is opened, and no escalation is recorded, for a signal that was never sent.
- An unexpected signalling failure surfaces as a termination fault instead of being swallowed into an ordinary unconfirmed release.
- The graceful and force periods are measured on a monotonic clock, so the documented full-period-after-the-actual-signal guarantee survives a wall-clock adjustment in either direction.
- The descendant-attribution claim in documentation, evidence, and audits matches exactly what the mechanism proves.

### Negative
- The process module grows one exported sequencer, one seven-member primitives interface carrying a trusted deadline scheduler, one adapter factory, one internal bounded-call helper that owns a per-call deadline, and one optional cancellation parameter.
- Every asynchronous primitive gains a required signal parameter, so every production implementation and every injected primitive set must accept and honour it, and the delivered `/proc` directory scan must learn to abandon its remaining iteration.
- The primitive interface grows to seven members across two trust classes, and every description of it must carry that distinction rather than calling all seven equally fallible.
- Pre-signal observation is now itself bounded, so a host whose identity read or listener probe is slower than the pre-signal allowance yields an unconfirmed release with no signal sent instead of a shortened graceful shutdown; that trade is deliberate, because a silently shortened graceful window is a false claim while an unconfirmed release is an honest one.
- A termination that begins after its root identity has already exited, with the owned group still populated, is now reported unconfirmed instead of being force-signalled; that case surfaces as an explicit non-success rather than a silent group kill.
- The termination outcome vocabulary grows from three values to four, so evidence readers and fixtures must learn `unconfirmed`.
- The signal primitive gains a return value and an error contract, so every injected primitive set must model a delivered send, a refused send, and a faulted send rather than a single silent call.
- Two clocks now coexist in the runtime modules — the monotonic termination clock and the delivered wall-clock timestamps — so every description, document, and evidence field must say which one it means.
- A graceful signal refused by the target-gone race yields `already-absent` only when its single bounded settlement audit completes and confirms; otherwise that stop is reported unconfirmed even though the owned group had in fact gone, and the retained ownership is re-attempted by the shutdown sweep.

### Neutral
- Production wiring is unchanged: `nodeRuntimeProcessAdapter` remains the default adapter over the default primitives, the production deadline is an ordinary `setTimeout` timer cleared on every exit path, and the existing `terminate(gracefulMs, forceMs, port)` call sites keep working because cancellation is optional.
- The documented overall bound, its configured inputs, and its default value are unchanged; the allowance split that makes the full phase windows fit inside it is derived inside the sequencer and adds no configuration.
- The audit shape, the `processGroupAbsent` field name, the loopback listener probe, and the ownership-record key are unchanged.
- The primitive set stays at exactly seven members in the same two trust classes, and the termination outcome vocabulary stays at exactly four values.
- The production deadline remains an independent native `setTimeout` timer, so the clock change does not touch the deadline mechanism, and the injected controlled clock still drives every deterministic sequencer test.
- No environment variable, flag, schema, migration, route, or deployment topology changes.
